Managing Talos machine config with patches, mise and hunk

Oct 11, 2026·9 min read· homelabkubernetes
AI-assisted
On this page
  • The question that started it
  • The mise tasks
  • Quick reference

My homelab cluster, portland, is three Dell OptiPlex 7060 Micros running Talos Linux. Everything inside Kubernetes is GitOps'd through Argo CD, but the Talos machine config underneath it was… not.

I'd been changing nodes with talosctl patch machineconfig, one patch at a time, and slowly losing track of what was actually on each box. This post walks through the workflow I ended up with.

The question that started it

I had a shared patch, patches/all-nodes.yaml, with settings every node needs: install disk, DNS, Longhorn mounts, metrics endpoints and so on.

Can I just keep re-running talosctl patch with this file every time I add something?

Watch out

talosctl patch mutates live state. Re-running it doesn't converge on what's in git.

The mise tasks

Each task renders a node's config from the base plus its patches, then hands the result to hunk for review.

mise.toml · toml 
# Render the full config for a single node
[tasks.render]
description = "Render machine config for a node"
run = "talosctl machineconfig patch base.yaml --patch @patches/all-nodes.yaml"
[tasks.diff]
depends = ["render"]
Note

Apply one node at a time so the control plane keeps quorum.

Quick reference

TaskWhat it does
mise run renderBuilds the full config from patches
mise run diffOpens a diff against the live node in hunk
mise run applyApplies to one node and waits for health
